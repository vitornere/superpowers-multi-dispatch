# Model tiers and fallback

Single source of truth for which model every external call uses. Other files name a tier; this file maps the tier to a model.

## Claude-family models run on Claude

Opus, Sonnet, Haiku, and Fable always run as Claude subagents through the Agent tool (`subagent_type` from the table, `model` set to `opus`, `sonnet`, `haiku`, or `fable`). Never send a `claude-*` model ID to Cursor.

Cursor runs only non-Claude models: Composer, Grok, GPT, and the like.

## Pinning rule

Every `multi:cursor-*` dispatch carries `--model <id>` taken from the tier table below. The Cursor CLI otherwise reuses whatever model the user last picked, so an unpinned call runs on an unknown model.

Put the flag in the Agent prompt, for example `--model composer-2.5 --read-only <question>`. The forwarding agents pass an explicit `--model` through verbatim.

Every Claude subagent dispatch sets `model` (and `effort` where the table gives one) explicitly.

Never pass `auto`. Never pick a model that is not in this table.

## Tier table

Each chain entry names its executor. Try entries in order. The last column is the final fallback once every chain entry failed to run.

| Tier | Used for | Chain (try in order) | Final fallback |
|---|---|---|---|
| `implement` | Default implementation, TDD increments, localized corrections | Cursor `multi:cursor-delegate --model composer-2.5` | Claude `general-purpose`, model `sonnet` |
| `implement-complex` | Implementation matching the complex criteria in [execution.md](execution.md) | Claude `general-purpose`, model `opus`, effort `high`; then Cursor `multi:cursor-delegate --model grok-4.7-high` | none: report the outage |
| `review` | Broad final review, both rounds | Cursor `multi:cursor-explore --model gpt-5.6-sol-high`; then Cursor `--model grok-4.7-high` | Claude `general-purpose`, model `opus`, effort `high`, read-only |
| `deep-read` | Adversarial plan critique; stuck root-cause investigation | Cursor `multi:cursor-explore --model gpt-5.6-sol-high`; then Cursor `--model grok-4.7-high` | Claude `general-purpose`, model `opus`, effort `high`, read-only |
| `explore` | Wide codebase sweeps | Cursor `multi:cursor-explore --model composer-2.5` | Claude `Explore` |
| `research` | External web, library, and API research | Cursor `multi:cursor-research --model composer-2.5` | Claude `general-purpose`, model `sonnet`, read-only |

Quota pools (from the user's Cursor plan):

* **Cursor pool:** `composer-*`, `grok-*`, `cursor-grok-*`.
* **Other pool:** every other Cursor model (here, `gpt-5.6-sol-high`).

When the Cursor pool runs out, Cursor itself spills into the Other pool. So a quota error on a Cursor-pool model means both pools are gone.

Never select automatically: `-fast` variants, `-xhigh`, `-max`, or any model labeled `NO ZDR`. Each needs the user's explicit request.

## Availability check

Once per session, before the first `multi:cursor-*` dispatch, run:

```bash
agent --list-models
```

Confirm every Cursor model ID in the tier table appears in the output. Claude subagent models are not checked here.

* **A model is missing:** tell the user in one line: `Model <id> (tier <tier>) is no longer listed by Cursor; update references/models.md.` Use the next model in that tier's chain. Do not edit this file yourself.
* **The `multi:cursor-*` agent types are not available** (the `multi` plugin is not installed or not enabled): Cursor is down for this session, same as below.
* **The command fails or `agent` is not installed:** Cursor is down for this session. Skip every Cursor entry, use the remaining Claude entries and final fallbacks, and tell the user once.

## Fallback

Cursor never blocks the workflow. A Cursor failure changes who executes. It never pauses the work to wait for the user.

Classify every chain entry that failed to run, then act:

| Failure | Action |
|---|---|
| Cursor quota or usage limit (`usage limit`, `quota`, `on-demand spend`, `limit reached`, HTTP 429 tied to usage) | Mark that model's pool exhausted for the session. Move to the next chain entry, skipping Cursor entries in exhausted pools. If none remains, use the final fallback. |
| Cursor unknown or unavailable model | Send the one-line model-missing notice above. Move to the next chain entry. |
| Cursor authentication failure, CLI missing, or erroring after one retry | Treat Cursor as down for the session. Skip every Cursor entry from now on. |
| Cursor transport error or timeout | Retry the same call once. On a second failure, treat it as above. |
| Claude subagent could not run (rate limit, overloaded, refused by the harness) | Retry once. On a second failure, move to the next chain entry. |
| The task itself went wrong (bad code, failing tests, wrong approach) | Not a fallback trigger. Follow the failure handling in [execution.md](execution.md). |

Remember exhausted pools and a down Cursor for the rest of the session. Do not probe them again on every task.

If every entry and the final fallback failed to run, report the outage to the user, keep the completed work, and continue with any remaining tasks that do not depend on the blocked one.

### Running a Claude subagent (chain entry or final fallback)

* Dispatch through the Agent tool with the `subagent_type`, `model`, and `effort` from the tier table.
* Give it the same prompt and context the Cursor call would have received, including the version-control prohibition and, for read-only tiers, a ban on modifying files.
* Every Superpowers step and every check Claude performs stays unchanged: diff inspection, verification, RED and GREEN observation, finding validation.

### Telling the user

* At the moment of fallback, one line in chat: `<failed executor and model> <reason>; <tier> now runs on <replacement>.` Then continue without waiting for a reply.
* Repeat the substitutions in the final report: which tiers fell back, why, and from which task onward.

## Red flags

| Thought | Reality |
|---|---|
| "The CLI already defaults to the right model" | The CLI defaults to the user's last pick. Pin `--model` on every call. |
| "Quota is gone, so I must stop and ask" | Quota is a fallback trigger. Fall back, notify in one line, keep going. |
| "Replacing Cursor with Claude hides the outage" | It does not if you announce it in chat and in the final report. |
| "Another Cursor model might still work" | Only one in a pool that is not exhausted. A Cursor-pool quota error means both pools are gone. |
| "This newer model looks better, use it" | Only models in this table. Suggest the change to the user instead. |
| "The model is gone, I'll update models.md" | The user owns this file. Notify them and use the chain. |
| "Cursor lists `claude-opus-*`, so route Opus through Cursor" | Claude-family models run as Claude subagents. Never through Cursor. |
